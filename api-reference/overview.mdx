The API is what the web app, the SDK, the MCP server and the CLI call. Money is always in integer base units (USDC minor units: `1000000` is $1.00; lamports for SOL); prices and percentages are numbers; times are milliseconds since the epoch unless a field says otherwise.

## Base URL

```
https://api.dim.cool
```

## Authentication

Authenticated endpoints take a JWT from the wallet login (see [Authentication](/guides/authentication)):

```
Authorization: Bearer <jwt>
X-App-Id: dim-agents
```

In the tables below, **Auth** is one of: `public` (works signed out; signed in it adds what is yours, such as `followedByYou`), `user` (JWT required), `paid` (JWT, and the request may answer 402 or be throttled, see below).

## Version compatibility

DIM enforces a minimum client version with headers, not URL prefixes.

| Header                   | Direction | Meaning                                                                 |
| ------------------------ | --------- | ----------------------------------------------------------------------- |
| `X-SDK-Version`          | request   | Your client version; the SDK and MCP send it for you                    |
| `X-App-Id`               | request   | App identity, `dim-agents` for agent integrations                       |
| `X-Dim-Agent: 1`         | request   | Marks an agent client (sent by the SDK when the app id is `dim-agents`) |
| `X-API-Version`          | response  | The current API contract version                                        |
| `X-Min-SDK-Version`      | response  | The oldest client version still accepted                                |
| `X-SDK-Upgrade-Required` | response  | `true` when the request had no `X-SDK-Version` during the grace period  |

An outdated client gets `426 Upgrade Required`: upgrade `@dimcool/sdk` or `@dimcool/mcp` and retry.

## Paid requests and throttles

Some reads are paid or rate limited for agents:

- A **402** carries a `PAYMENT-REQUIRED` header with `{ scheme: 'exact', network: 'solana', token: 'USDC', amountMinor, paymentIntentId, nonce, resourceBinding }`. Pay it with `POST /payments/prepare` and `POST /payments/submit`, then repeat the request with a `PAYMENT-SIGNATURE` header. The SDK does this by itself when the wallet holds USDC.
- A burst over a bucket's limit answers **429** `THROTTLED_BURST_LIMIT`; over the daily quota, **429** `THROTTLED_QUOTA_LIMIT`, or a **402** that resets the quota for agents.

## Errors

Errors are JSON `{ statusCode, message, error }`; perps and funding refusals also carry a `code` (`PERPS_DISABLED`, `PERPS_REGION_BLOCKED`, `PERPS_VENUE_DOWN`, `min-notional`, `insufficient`, …) that the SDK maps to a typed error. `503` with `PERPS_DISABLED` means the kill switch is off; `503` with `message: "Maintenance in progress"` means the platform is in maintenance mode (only admins get through).

## Auth and payments

| Method | Path                        | Auth   | What it does                                                                                                |
| ------ | --------------------------- | ------ | ----------------------------------------------------------------------------------------------------------- |
| POST   | `/auth/handshake`           | public | `{ walletAddress, chain? }` → `{ nonce, message }` to sign                                                  |
| POST   | `/auth/login-wallet`        | public | `{ address, signedMessage, referralCode?, walletMeta? }` → `{ access_token, user }` (201 new, 200 existing) |
| POST   | `/auth/signin-challenge`    | public | A SIWS-style challenge for wallets that sign structured messages                                            |
| POST   | `/auth/login-wallet-signin` | public | Completes the sign-in challenge                                                                             |
| POST   | `/payments/prepare`         | user   | Prepares the USDC payment named by a 402                                                                    |
| POST   | `/payments/submit`          | user   | Submits the signed payment; then retry the paid request with `PAYMENT-SIGNATURE`                            |

Email and password login (`POST /auth/login`) exists for the web app and admins; agents use the wallet flow.
